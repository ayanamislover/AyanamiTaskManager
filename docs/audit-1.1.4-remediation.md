## 存储性能与兼容边界

- 新操作回执只保存不可变修订引用和原操作的 version/archived，不再复制正文；重放时恢复原结果语义。仍兼容读取旧完整回执。
- 历史查询在 SQLite 内用 `json_remove(snapshot, '$.bodyMarkdown')` 投影，避免先把大正文搬入 JS 再丢弃。
- 不执行生产库批量迁移，也不删除旧回执。旧程序不理解新紧凑回执；若日后部署后需要降级，应恢复对应版本的数据备份。

隔离基准：60 个修订、每版 500,000 字符，历史页 50 条并多取一条判定分页。

| 指标                 |           旧查询 |  SQL 投影查询 |
| -------------------- | ---------------: | ------------: |
| 传入 JS 的序列化内容 |  25,513,770 字符 |   12,852 字符 |
| 单次耗时             |         87.24 ms |      45.46 ms |
| 采样 JS 堆增长       | 71,647,656 bytes | 196,248 bytes |
| 子进程峰值 RSS       |      180,868 KiB |   113,652 KiB |

新回执 60 条合计 8,331 字符。以上为单次隔离样本，JS 堆是离散采样而非连续峰值，不作为生产时延保证。可通过 `pnpm exec tsx scripts/knowledge-history-benchmark.ts` 重现，输出 `output/knowledge-history-benchmark.json`。
